1. Основной вопрос: Зачем нужен файл .gitignore? Что произойдёт, если мы закоммитим папку
node_modules?
блэклист файлов которые не должны попасть в облако. в облако попадет папка c гигиабайтами ненужной информации
2. Вопрос на понимание: Как вы думаете, почему файл с паролями (.env) должен быть в .gitignore?
(Подсказка: GitHub — это публичный сайт. Если код видят все, что случится с вашими паролями?)
так как боты подхватят это за несколько секунд и пароли нужно будет менять
3. Вопрос на терминологию: Что такое Глоссарий и зачем его вести?
для быстрого просмотра термитнов и укладывания информации по полкам
4. Вопрос с подвохом (на М0-03): В файле .gitignore написано *.log. Если у вас в проекте есть файлы
test.log, debug.log и config.json, какие из них Git проигнорирует и почему?
все которые имеют расширение лог проигнорируются гитом и отправится только конфиг.джсон так как в гит.игноре есть условие *.log
5. Вопрос на «снежный ком» (Итоги Модуля 0): Давайте проверим всю цепочку. Опишите по шагам,
что произойдёт, если вы:
Создали файл test.txt (терминал)
Написали в нём код (VS Code)
Сохранили его (Ctrl+S)
Сделали git add . и git commit (Git)
Сделали git push (GitHub)
Удалили файл на компьютере (терминал)
(Подсказка: пропадёт ли файл с GitHub?)
нет не пропадет, файл удален только локально что бы его удалить нужно отправить новый комит в гитхаб
6. Вопрос на применение: Как посмотреть, какие файлы Git игнорирует в данный момент? (Подсказка:
в интернете найдите команду git status --ignored или просто доверьтесь логике). использовать команду git status --ignored или git check-ignore <имя_файла>
