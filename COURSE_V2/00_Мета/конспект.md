## М0-01. Терминал и структура проекта

Терминал — окно, оболочка — программа внутри.
На Windows: PowerShell (современная) и cmd (старая).
Примеры из интернета с $, sudo, -p — это bash,
они не работают в PowerShell.
Мои команды:

- Где я .................. Get-Location (коротко: pwd)
- Что вокруг ............. Get-ChildItem (коротко: ls, dir)
- Перейти ................ Set-Location (коротко: cd)
- Создать папки .......... New-Item -ItemType Directory -Force -Path "a","b"
- Создать файл ........... New-Item -ItemType File -Path "путь\файл.md"
- Проверить существование . Test-Path -PathType Container "папка"
- Примерка удаления ...... Remove-Item -Recurse -WhatIf "папка"
  Ловушки:

1. mkdir -p — нет в PowerShell, вместо -p работает -Force.
2. Несколько путей — через запятую, иначе вторая
   папка создастся ВНУТРИ первой.
3. Пробел в имени — кавычки.
4. cd и другой диск: в cmd нужен /d, в PowerShell не нужен.
5. Перед удалением — Get-Location. Всегда.

## М0-03. Файлы и папки

Порядок массовой операции: посмотреть -> посчитать -> сделать.
Команды:

- Список ............. Get-ChildItem -File (-Directory, -Force, -Recurse)
- Скопировать ........ Copy-Item "откуда" "куда"
- Переместить ........ Move-Item ... -Destination "папка"
- Переименовать ...... Get-ChildItem ... | Rename-Item -NewName { ... }
- Удалить ............ Remove-Item "путь\*" (-Recurse для папки)
- Примерка ........... любой команде добавить -WhatIf
- Точное имя ......... -LiteralPath (когда в имени [ или ])
- объединение файла .. -Raw объединить файл в одну строку и сохранить оригинальные символы переноса строк, не удаляя их.
- Совпадение ......... -match — сравнение по образцу
- Отбор .............. -Filter "маска" (быстрее и надёжнее -Include)
  Правила:

1. Remove-Item НЕ в корзину. Удалять только то, что в git или в \_trash.
2. Удаляем содержимое папки (\*), а не саму папку.
3. Перед move/copy: Test-Path назначения.
4. 7 + 3 = 10: после операции сверяй числа, а не "вроде".
5. Copy-Item НЕ создаёт папку назначения - создай её сам.
   Эксперимент (моя машина, PS 5.1): <впиши, что сделали Copy-Item и Move-Item
   Move-Item выдает ошибку если есть файл с таким же именем

## М0-05. Git: три зоны и четыре отката

Мой корень репозитория: C:\Users\lfyz\QA-Learning-2026
Здесь же package.json и node_modules. Учебные папки - внутри COURSE_V2.
Три зоны: диск --git add--> индекс --git commit--> история --git push--> GitHub
Каждый урок про git начинаю с:
Set-Location "C:\Users\lfyz\QA-Learning-2026" ; Get-Location ; git status
Команды:

- Статус .................. git status
- Разница ................. git diff (диск против индекса), git diff --staged
- В индекс ................ git add "путь" (сначала status, потом add)
- Коммит .................. git commit -m "что сделано"
- История ................. git log --oneline
- Откат 1 (файл изменён) .. git restore "путь"
- Откат 2 (в индексе) ..... git restore --staged "путь"
- Откат 3 (коммит, не push) git reset --soft|--mixed HEAD~1
- Откат 4 (уже в GitHub) .. git revert HEAD
- Игнор ................... git check-ignore -v node_modules

Для новой машины
git config --global user.name "Name"
git config --global user.email "email@example.com"
git config --global init.defaultBranch main
git config --global core.quotepath false отображение кириллицы
git config --global core.editor "code --wait"

Правила:

1. --hard теряет изменения безвозвратно.
2. Отправленный коммит отменяется только revert.
3. .gitignore не убирает уже отслеживаемое: git rm -r --cached
4. Проверка: COURSE_V2\00_Мета\проверка-git.ps1 -> 5 из 5

Если коммит уже в GitHub — только revert.
